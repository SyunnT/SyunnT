## 一、错误报告

- `void perror(char const *message);`：用于输出错误提示信息`message`以及程序最近遇到的一个错误的解释

`perror`的运行依赖于定义于`errno.h`中的一个整型变量`errno`，当程序发生错误时，`errno`的值会被更改为该错误代码，`perror`的行为就是先将`message`打印出来，这通常是一条错误提示信息，然后再打印当前`errno`值对应的错误解释



## 二、终止执行

- `void exit(int status);`：终止程序并返回状态码`status`

这个函数定义于`stdlib.h`，它用于在程序任何地方退出整个程序并返回状态码。和`return`语句不同的是，`return`只能退出函数。

`stdlib.h`定义了两个常用的状态码符号：`EXIT_SUCCESS`和`EXIT_FAILURE`，可以适用于大部分情况



## 三、流与缓冲区

流是一个抽象的概念，但每个流几乎都会关联程序中的一个 I/O 缓冲区，我们可以将这个缓冲区看作是它的实体（实际上应该是有区别的）。

这个缓冲区足够大，其行为和队列类似，对于一个输出流，字符串通过输出函数从流所关联的缓冲区的一端依次进入，当流实际执行输出到输出目标的操作时，字符串就通过缓冲区的另一端依次输出；而对于一个输入流，如果输入函数在调用时缓冲区内没有数据流就会从输入目标获取输入，它们被保存在输入流的缓冲区中，当输入函数调用时，就会从这个缓冲区获取数据，和输出流一样，输入流也是类似于队列的实现。

输出流缓冲区只有被写满的时候才会刷新到设备或文件中，而输入流缓冲区为空时会通过从设备或文件读取下一块较大的输入，重新填充缓冲区。

标准输出和输入流通常是联系的，当请求输入时会刷新输出缓冲区，从而保证在获取输入前用户能看到一些提示信息。如果一个程序只有输出操作，如果在程序执行过程中异常退出时输出缓冲区没有写满，那么在程序退出位置之前调用的那些输出函数中的字符串可能并不会被输出。

### 1. 文本流与二进制流

文本流的部分特性在不同的系统中可能不同：

- 其一是文本行的最大长度。标准规定至少允许 254 个字符
- 其二是文本行的结束方式。在 Windows 系统中，文本文件约定以一个回车符和一个换行符结尾。但是在 Unix 系统只使用一个换行符结尾

****

二进制流中的字节将完全根据程序编写它们的形式写入到文件或设备中，而且完全根据它们从文件或设备读取的形式写入到程序中。这种类型的流适用于非文本数据，如果不希望 I/O 函数修改文本文件的行末字符，也可以把它用于文本文件。



### 2. 文件

在 C 语言，一共只有两种类型的流对象，一种是文件，另一种是字符串。

对于标准 I/O，它们虽然联系的目标是设备，但和 Linux 的处理方式一样，都可以将它们看作文件。

文件类型的流用`FILE`结构进行管理，通常我们使用的是一个指向`FILE`类型的指针，每个流都有一个相应的`FILE`结构与它关联。

对于每个 C 程序，运行时系统必须提供至少 3 个流 —— 标准输入（`stdin`）、标准输出（`stdout`）和标准错误（`stderr`），它们都是一个指向`FILE`结构的指针。标准输入默认情况下为键盘设备，标准输出为终端或屏幕，可以通过终端的重定向功能将输入输出设备修改为其他文件。



### 3. 标准 I/O 常量

`<stdio.h>`中定义了许多 I/O 相关的常量：

- `EOF`：提示到达了文件尾，比`char`要长，故不能用`char`来保存
- `FOPEN_MAX`：一个程序同时最多能够打开的文件数量。与编译器有关，其值包括 3 个标准流在内至少为 8
- `FILENAME_MAX`：编译器支持的最长合法文件名的长度



## 四、操纵流

### 1. 分类

**I/O 对象**：

所有的读写操作对象可以分为两类，其一是`FILE*`类型的变量，其二是内存中的字符串。而对于`FILE*`类型的变量又可以根据函数的特定性分为两类，其一是标准 I/O 对象，其二是通用的`FILE*`变量

**I/O 操作**：

I/O 操作按照读写数据格式可以分为三类：单个字符、文本行（非格式化和格式化）、二进制数据

也可以按照针对的流分为三类：所有流、仅用于`stdin`和`stdout`、仅用于内存中的字符串

可以将所有 I/O 操作整理为下表：

| 格式       | 用于所有 FILE 流 | 仅用于`stdin`和`stdout` | 仅用于内存中的字符串 |
| ---------- | ---------------- | ----------------------- | -------------------- |
| 字符输入   | `fgetc`、`getc`  | `getchar`               | （无）               |
| 字符输出   | `fputc`、`putc`  | `putchar`               | （无）               |
| 文本行输入 | `fgets`          | `gets`                  | （无）               |
| 文本行输出 | `fputs`          | `puts`                  | （无）               |
| 格式化输入 | `fscanf`         | `scanf`                 | `sscanf`             |
| 格式化输出 | `fprintf`        | `printf`                | `sprintf`            |
| 二进制输入 | `fread`          | （无）                  | （无）               |
| 二进制输出 | `fwrite`         | （无）                  | （无）               |



### 2. FILE 对象

使用一个`FILE`对象的一般情况是使用指向`FILE`结构的指针，其过程包括打开流（创建`FILE`指针，并创建其实体，令其与某文件绑定），使用流，关闭流（删除`FILE`实体）。

#### 打开流

通过下面这个函数打开文件，并返回与这个文件绑定的`FILE`实体的指针：

```c
FILE *fopen(char const *name, char const *mode);
```

- 第一个参数`name`是希望打开的文件或设备的名字，可以是文件的相对位置，基础地址是可执行程序所在的位置；也可以是绝对位置

- 第二个参数`mode`是打开文件的方式，需要注意的是这里需要传入的参数是一个字符串，下面是一些常用的模式：

  |        | 只读   | 只写   | 添加（只写） | 读写    | 读写    | 添加（读写） |
  | ------ | ------ | ------ | ------------ | ------- | ------- | ------------ |
  | 文本   | `"r"`  | `"w"`  | `"a"`        | `"r+"`  | `"w+"`  | `"a+"`       |
  | 二进制 | `"rb"` | `"wb"` | `"ab"`       | `"r+b"` | `"w+b"` | `"a+b"`      |

  - 以`"r"`或其派生模式打开的文件必须预先存在，否则打开失败；以`"w"`、`"a"`或其派生模式打开的文件如果不存在则创建之，如果存在，对于`"w"`及其派生模式，将清空原有内容，对于`"a"`及其派生模式，将仅打开文件。
  - `"r"`、`"w"`及其派生模式打开文件后，读写指针在文件开头；`"a"`及其派生模式打开文件后，读写指针在文件末尾
  
- 返回值：若打开成功，则返回与文件绑定的`FILE`结构指针；若打开失败，则返回`NULL`

****

如果一个文件要换种模式重新打开，那么可以使用下面的函数：

```c
FILE *freopen(char const *filename, char const *mode, FILE *stream);
```

- 前两个参数和`fopen`中的参数相同，第三个参数就是需要重新打开的流，函数首先试图关闭这个流，然后用指定的文件和模式重新打开这个流。如果打开失败，那么函数返回一个NULL值。如果打开成功，则返回第三个参数值（它们是同一个实体，不过打开失败后，函数会自己将这个实体释放并返回 NULL）



#### 关闭流

使用`fclose`关闭一个流：

```c
int fclose(FILE *f);
```

- 对于输出流，`fclose`函数会在文件关闭之前刷新缓冲区。
- 执行成功返回 0，否则返回 EOF



#### 刷新和定位

- 刷新：迫使一个输出流的缓冲区内的数据进行物理写入

  ```c
  int fflush(FILE *stream);
  ```

- 定位：将写入或读取流的位置定位至指定位置

  ```c
  long ftell(FILE *stream);
  int fseek(FILE *stream, long offset, int from);
  ```

  - `ftell`函数返回流的当前位置，即当前位置据起始位置的字节数。在二进制流中，这很自然。但是在文本流中，这个值并不一定准确地表示当前位置和文件起始位置之间的字符数，因为有些系统将对行末字符进行翻译转换，特别是对于非单字节 ASCII 码的文件，此时一个字符并非一个字节。

  - `fseek`函数改变流所在文件中的位置，`offset`和`from`共同决定一个位置：

    | `from`     | 定位到                                                       |
    | ---------- | ------------------------------------------------------------ |
    | `SEEK_SET` | 从流的起始位置起`offset`个字节，`offset`必须是一个非负值（通常由`ftell`获取） |
    | `SEEK_CUR` | 从流的当前位置起`offset`个字节，`offset`的值可正可负         |
    | `SEEK_END` | 从流的尾部位置起`offset`个字节，`offset`的值可正可负。如果它的值是正值，将定位到文件尾的后面 |

    > 试图定位到一个文件的起始位置之前是一个错误。定位到文件尾之后并进行写入将扩展这个文件，定位到文件尾之后并进行读取将导致返回一条“到达文件尾”的信息。在二进制流中，从`SEEK_END`进行定位可能不被支持，所以应该避免。。在文本流中，如果`from`是`SEEK_CUR`或`SEEK_END`，`offset`必须是 0。如果`from`是`SEEK_SET`，`offset`必须是一个从同一个流中以前调用`ftell`时所返回的值。

    用`fseek`改变一个流的位置有 3 个副作用：

    1. 行末指示字符会被清除
    2. 如果在`fseek`之前使用`ungetc`将一个字符返回流中，这个被退回的字符会被丢弃
    3. 定位允许从写入模式切换到读取模式，或者回到打开的流以便更新

- 更严格的定位函数：

  ```c
  void rewind(FILE *stream);
  int fgetpos(FILE *stream, fpos_t *position);
  int fsetpos(FILE *stream, fpos_t const *position);
  ```

  - `rewind`函数将读/写指针设置回指定流的起始位置，同时清楚流的错误提示标志
  - `fgetpos`和`fsetpos`分别是`ftell`和`fseek`函数的替代方案。`fgetpos`将位置信息写入到`fpos_t`指针指向的内存中，`fsetpos`接受这样一个类型的指针作为参数来设置位置。



#### 改变缓冲方式

当指定的流被打开但是还没有在它上面执行任何其他操作前，可以调用下面两个函数改变缓冲方式：

```c
void setbuf(FILE *stream, char *buf);
int setvbuf(FILE *stream, char *buf, int mode, size_t size);
```

- `setbuf`设置了另一个数组，用于对流进行缓冲。这个数组的字符长度必须为`BUFSIZ`（定义于`stdio.h`）。为一个流自行指定缓冲区可以防止 I/O 函数库为它动态分配一个缓冲区。如果用一个`NULL`参数调用这个函数，`setbuf`函数将关闭流的所有缓冲方式。字符准确地按程序所规定的方式进行读取和写入。

  > 需要注意：如果在关闭流之前这个数组内存被释放，流仍然会访问这块内存

- `setvbuf`和`setbuf`类似，`mode`用于指定缓冲的类型，`_IOFBF`指定一个完全缓冲的流，`_IONBF`指定一个不缓冲的流，`_IOLBF`指定一个行缓冲流。`buf`和`size`参数用于指定需要使用的缓冲区，如果`buf`为 NULL，那么`size`的值必须是 0



#### 流错误函数

下面的函数用于判断或改变流的状态：

```c
int feof(FILE *stream);
int ferror(FILE *stream);
void clearerr(FILE *stream);
```

- `feof`：如果流当前处于文件尾，`feof`返回真
- `ferror`：报告流的错误状态，如果出现任何读/写错误，函数就返回真
- `clearerr`：对指定流的错误标志进行重置



#### 临时文件流

```c
FILE *tmpfile(void);
```

创建一个临时文件并返回与之关联的流。该文件以`wb+`模式打开，当文件被关闭或程序终止时，这个文件将自动删除。

****

```c
char *tmpnam(char *name);
```

用于创建临时文件的名字。如果传递`NULL`，则返回一个指向静态数组的指针，该数组包含了被创建的文件名；否则，参数假定是一个指向长度至少为`L_tmpnam`的字符数组的指针，文件名被创建为该数组的值，并返回该参数。



### 3. I/O 函数

#### 字符 I/O

**输入：**

- 适用于所有 FILE 流
  - `int fgetc(FILE *stream);`
  - `int getc(FILE *stream);`
- 仅适用于`stdin`
  - `int getchar(void);`

**行为**：从传入的流或`stdin`中读取下一个字符，并把它作为函数的返回值返回，如果流中不存在更多的字符，函数就返回`EOF`

****

**输出：**

- 适用于所有 FILE 流
  - `int fputc(int character, FILE *stream);`
  - `int putc(int character, FILE *stream);`
- 仅适用于`stdout`
  - `int putchar(int character);`

**行为**：第 1 个参数是要被打印的字符，在打印之前，函数将这个整型参数裁剪为一个无符号字符型值，如果写入失败则返回`EOF`

****

**撤销字符 I/O**：

`ungetc`函数用于将读取到的一个字符退回到流中，比如有时我们的条件是读到某个非某类型的数据时停止读取，那么总会多读取一个字符，如果这个字符是需要用于后续读取的话，我们就可以使用`ungetc`将这个字符退回到流中，其原型为：

```c
int ungetc(int character, FILE *stream);
```

每个流都允许至少退回一个字符，退回的字符放在流下一个将被读取的字符之前。所以如果一个流允许退回多个字符，那么这些字符再次被读取的顺序就以退回时的反序进行。

**注意**：

- `ungetc`退回的字符只修改流，而不会修改与之关联的文件
- 退回字符和流的当前位置有关，所以如果用`fseek`、`fsetpos`或`rewind`函数改变了流的位置，所有退回的字符都将被丢弃。



#### 未格式化行 I/O

**输入**：

- 所有 FILE 流：`char *fgets(char *buffer, int buffer_size, FILE *stream);`
- 仅`stdin`：`char *gets(char *buffer);`

**行为**：

- `fgets`读取到一个换行符或`stream`的缓冲区中存储的字符数达到`buffer_size-1`个时停止读取。如果读取到了换行符，那么这个换行符会写入到`stream`的缓冲区中。然后将整个读取到的字符串写入到`buffer`中，并在末尾添加`NUL`字节。若未读取任何内容就到达了文件尾，则返回`NULL`；否则返回`buffer`
- `gets`的行为和`fgets`基本相同，不过它并不安全。由于没有`buffer_size`的限定，`gets`会一直读取字符直到遇到换行符或者文件尾，然后将读到的内容写入到`buffer`中并添加`NUL`字节，不管`buffer`本身有多长。另一个区别是读到的换行符不会写入`buffer`

****

**输出**：

- 所有 FILE 流：`char *fputs(char const *buffer, FILE *stream);`
- 仅`stdout`：`char *puts(char const *buffer);`

**行为**：

- `fputs`按标准字符串形式输出`buffer`的内容，所以其必须以`NUL`字节结尾。`fputs`不对输出的字符串做额外的工作，仅按原样输出字符串。若输出时出现了错误，`fputs`返回`EOF`，否则返回一个非负值。
- `puts`的行为和`fputs`几乎完全相同，唯一的区别是`puts`会在`buffer`的基础上在末尾输出一个换行符



#### 格式化行 I/O

**输入**：

- 所有 FILE 流：`int fscanf(FILE *stream, char const *format, ...);`
- 仅`stdin`：`int scanf(char const *format, ...);`
- 仅字符串：`int sscanf(char const *string, char const *format, ...);`

每个输入函数除了输入流不同之外，其余行为完全相同。当格式化字符串到达末尾或者读取的输入不再匹配格式字符串所指定的类型时，输入就停止。在任何一种情况下，被转换的输入值的数目作为函数的返回值返回。如果在任何输入值被转换之前文件就已到达尾部，函数就放置常量值 EOF。

省略符形参中传入的应该是变量的指针，需要注意的是这些指针参数的类型必须是对应格式代码的正确类型，函数并不检查它们是否匹配。

`scanf`函数家族中的`format`字符串参数可能包含下列内容：

- 空白字符：它们与输入中的零个或多个空白字符匹配，在处理过程中将被忽略；
- 格式代码：它们指定函数如何解释接下来的输入字符
- 其他字符：当其他任何字符出现在格式字符串时，下一个输入字符必须与它匹配。如果匹配，该输入字符随后就被丢弃。如果不匹配，函数就不再读取而是直接返回

`scanf`格式代码：由百分号`%`开头，后面接上一个可选的星号`*`，一个可选的宽度，一个可选的限定符，格式代码。

- 星号：使转换后的值被丢弃而不是被存储。当输入已经固定了，但其中的某些数据并不需要时可以使用这个技巧

- 宽度：一个非负的整数，用于限制将被读取用于转换的输入字符的个数。如果未给出宽度，函数就连续读入字符

- 格式代码：

  | 代码                                                         | 含义                                                         |
  | ------------------------------------------------------------ | ------------------------------------------------------------ |
  | `d`                                                          | 按十进制读入一个`int`                                        |
  | `i`                                                          | 读入`int`，根据输入数据的前缀决定该数据的基数。<br />无前缀为十进制，前缀`0`为八进制，前缀`0x`/`0X`为十六进制 |
  | `u`                                                          | 按十进制读入一个`unsigned`                                   |
  | `o`                                                          | 按八进制读入一个`unsigned`，`0`前缀为可选输入                |
  | `x`/`X`                                                      | 按十六进制读入一个`unsigned`，`0x`/`0X`前缀为可选输入，且即使输入前缀为`0`而非`0x`也将被解释为十六进制 |
  | `f`<br />`e`/`E`<br />`g`/`G`<br />`a`/`A`（C99 新增）       | 读入一个`float`，每种形式都可以按常规浮点数写法或科学计数写法写出 |
  | `c`                                                          | 读入一个`char`或`char`序列，如果在为该格式代码读入输入时，输入中前导的空白字符不会被忽略。<br />如果未指定宽度，那么只读入一个`char`；<br />如果指定了宽度，就读入一个`char`序列，此时用于接受该值的字符指针应该指向一个字符数组，<br />序列后不会添加`NUL`字符，数组长度要足够大 |
  | `s`                                                          | 读取一串非空白字符。参数必须指向一个足够大的字符数组。<br />当发现空白时输入就停止，字符串后面会自动加上`NUL`字符 |
  | `[xxx]`<br />(每个`x`是一个字符，`[xxx]`表示多个字符的集合，<br />这个集合如果以`^`开头，表示后续所有字符构成集合的补集，<br />右方括号`]`如果要放在这个集合中必须是列表中的第1个字符) | 从输入中不断读取字符，直到遇到第 1 个非`[xxx]`集合中的字符位置，字符串后面会自动加上`NUL`字符。 |
  | `p`                                                          | 输入预期为一串字符，这串字符应该像`printf`函数的`%p`格式代码所产生的输出。 |
  | `n`                                                          | 不读取任何输入，向参数写入`scanf`函数到遇到这个格式代码为止从输入读取的字符数 |

- 限定符：用于修改读入`int`、`unsigned`、`float`等类型的格式代码的默认转换类型

  | 格式代码      | `h`              | `l`             | `L`           | `ll`（从此开始C99新增） | `z`      | `hh`            | `j`         | `t`         |
  | ------------- | ---------------- | --------------- | ------------- | ----------------------- | -------- | --------------- | ----------- | ----------- |
  | `d`、`i`、`n` | `short`          | `long`          |               | `long long`             | `size_t` | `signed char`   | `intmax_t`  | `ptrdiff_t` |
  | `o`、`u`、`x` | `unsigned short` | `unsigned long` |               | `unsigned long long`    | `size_t` | `unsigned char` | `uintmax_t` | `ptrdiff_t` |
  | `e`、`f`、`g` |                  | `double`        | `long double` |                         |          |                 |             |             |

****

**输出**：

- 所有 FILE 流：`int fprintf(FILE *stream, char const *format, ...);`
- 仅`stdout`流：`int printf(char const *format, ...);`
- 仅字符串：`int sprintf(char *buffer, char const *format, ...);`（注意该函数没有说明`buffer`尺寸的参数，所以可能会造成访问内存越界）

`printf`格式代码：以`%`开头，紧跟零个或多个标志字符，一个可选的最小字段宽度，一个可选的精度，一个可选的修改符，格式代码

- 格式代码

  | 代码               | 含义                                                         |
  | ------------------ | ------------------------------------------------------------ |
  | `d`、`i`           | 参数作为一个十进制整数打印。<br />如果给出了精度而且值的位数少于精度位度，前面就用 0 填充 |
  | `u`                | 参数作为一个十进制无符号值打印                               |
  | `o`                | 参数作为一个八进制无符号值打印                               |
  | `x`/`X`            | 参数作为一个十六进制无符号值打印，`x`打印时`a~f`小写打印，`X`打印时`A~F`大写打印 |
  | `f`                | 参数作为一个`double`类型打印。按常规格式打印，精度决定小数点后面的位数，缺省值为 6 |
  | `e`/`E`            | 作为`double`类型打印，参数根据指数形式打印。小数点后面的位数由精度字段决定，缺省值为 6。`e`打印时指数前为`e`；`E`打印时指数前为`E` |
  | `g`/`G`            | 作为`double`类型打印，参数以`%f`或`%e`（`G`则`%E`）的格式打印，取决于其值。<br />如果指数大于等于`-4`但小于精度字段，就使用`%f`格式，否则使用指数格式 |
  | `c`                | 接受一个`int`类型值，如果传入的是`char`则先扩展为`int`，然后被裁剪为`unsigned char`类型并作为字符打印 |
  | `s`                | 接受一个`char*`值，打印一个字符串，遇到`NUL`字符结束         |
  | `p`                | 接受一个`void*`值，指针指被转换为一串因编译器而异的可打印字符并打印 |
  | `n`                | 接受一个`int*`值，它不产生任何输出，到遇到这个格式代码为止，函数所产生的输出字符数将写入到对应的参数中 |
  | `a`/`A`（C99新增） | 浮点数、十六进制数和`p`计数法                                |

- 标志字符

  | 标志 | 含义                                                         |
  | ---- | ------------------------------------------------------------ |
  | `-`  | 值在字段中左对齐，缺省情况下是右对齐                         |
  | `0`  | 当数值左对齐时，无效；当数值右对齐时，缺省情况是使用空格填充左边未使用的列，该标志表示用零填充。<br />可用于打印整数和浮点数的格式代码，对于打印整数的格式代码，如果给出了精度字段，这个标志将被忽略 |
  | `+`  | 当用于一个格式化某个有符号值的代码时，如果值非负，该标志会给它加上一个正号，缺省情况下，正号不显示 |
  | 空格 | 只用于转换有符号值的代码。当值非负时，这个标志把一个空格添加到它的开始位置。如果空格和正号标志同时给出，空格标志将被忽略 |
  | `#`  | 用于`o`时：将在非零数值前添加`0`前缀<br />用于`x`/`X`时：将在数值前添加`0x`/`0X`前缀<br />用于`e`/`E`、`f`时：确保结果始终包含一个小数点，即使它后面没有数字<br />用于`g`/`G`时：和`e`/`E`、`f`代码相同。另外，小数部分的尾缀 0 并不从小数中去除 |

- 字段宽度：一个十进制整数，用于指定将出现在结果中的最小字符数。如果值的字符数少于字段宽度，就对它用空白或`0`进行填充，以及填充在左边或者右边

- 精度字段：以一个句点开头`.`，用以与字段宽度隔开，值默认为 0。对于打印整数的格式代码，精度字段指定将出现在结果中的最小的数字个数并覆盖 0 标志。如果转换后的值的位数小于宽度，就在它的前面插入 0。如果值为 0 且精度也为 0，则转换结果就不会产生数字。对于`e`/`E`和`f`类型的转换，精度决定将出现在小数点后的数字位数，对于`g`/`G`类型的转换，精度将决定出现在结果中的最大有效位数。当使用`s`类型的转换时，精度将决定被转换的最多字符数。

  > 如果用于表示字段宽度和/或精度的十进制整数由一个星号代替，那么`printf`的下一个参数（必须是个整数）就提供宽度和/或精度。

#### 二进制 I/O

```c
size_t fread(void *buffer, size_t size, size_t count, FILE *stream);
size_t fwrite(void *buffer, size_t size, size_t count, FILE *stream);
```

- `buffer`是即将被读取或写入的内存空间，`size`是`buffer`中每一个元素的字节大小，`count`是`buffer`中的元素数量



### 4. 文件操纵函数

```c
int remove(char const *filename);
int rename(char const *oldname, char const *newname);
```

- `remove`删除一个指定的文件。如果当`remove`被调用时文件处于打开状态，其结果取决于编译器。如果成功则返回 0，否则返回非零值
- `rename`将文件从`oldname`改名为`newname`。如果已经有一个名为`newname`的文件存在，则其结果取决于编译器。操作成功返回 0，否则返回非零值。如果这个函数失败，文件仍然可以用原来的名字进行访问。
