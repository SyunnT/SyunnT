命名空间分隔了全局命名空间，每个命名空间是一个作用域，我们可以在某个命名空间中定义库的名字，那么库的作者（以及用户）可以避免全局名字固有的限制。

## 一、命名空间定义

命名空间的定义格式如下：

```cpp
namespace NS_Name {
    // ...
}
```

- 以`namespace`关键字开头，随后紧跟命名空间的名字。在命名空间名字后面是一系列由花括号括起来的声明和定义。
- 花括号中，只要能出现在全局作用域中的声明就能置于命名空间内，主要包括：类、变量（及其初始化操作）、函数（及其定义）、模板和其他命名空间。
- 和其他名字一样，命名空间的名字也必须在定义它的作用域内保持唯一。
- 命名空间既可以定义在全局作用域内，也可以定义在其他命名空间中，但是不能定义在函数或类的内部。
- 命名空间可以是不连续的
- `#include`不应该放在命名空间内部



## 二、成员定义

命名空间内的成员可以定义在命名空间内，也可以定义在命名空间外。

如果定义在命名空间内，那么就和正常定义的形式相同。

如果定义在命名空间外，那么需要先使用作用域运算符指定命名空间。和定义在类外的成员一样，返回类型（如果是命名空间中声明的类型）和被声明的名字需要使用作用域运算符，而后续的定义内容就不再需要了。

另外，需要注意的是，定义在类外的成员只能在其所属命名空间的外层空间中，不能在一个不相关的作用域中定义。



## 三、全局命名空间

全局作用域中定义的名字定义在全局命名空间中。全局命名空间以隐式的方式声明，并且在所有的程序中都存在。全局作用域中定义的名字被隐式地添加到全局命名空间中。

使用作用域运算符访问全局命名空间的方式就是省略命名空间的名字：

```cpp
::global_name
```



## 四、嵌套命名空间

- 内层命名空间的名字将隐藏外层命名空间声明的同名成员。
- 外层命名空间中的代码如果要访问内层命名空间的成员，需要从该成员所处命名空间开始逐层添加作用域运算符进行访问。



## 五、内联命名空间

- 内联命名空间中的名字可以直接被外层命名空间使用，就像是直接声明在外层命名空间一样

- 定义内联命名空间的方式是在关键字`namespace`前添加关键字`inline`：

  ```cpp
  inline namespace name{
      // ...
  }
  ```

- `inline`必须出现在命名空间第一次定义的时候，后续再打开该命名空间时可以写`inline`，也可以不写

- 内联命名空间和其所属的直接外层命名空间不应该有同名成员，否则在访问内联命名空间成员时必须显示声明作用域，而访问其所属的外层命名空间的成员时，则会出现指向不明确的错误



## 六、无名命名空间

- 无名命名空间是指没有任何名字进行限定的命名空间
- 每个文件都有一个无名命名空间，一个无名命名空间能在某个给定的文件中不连续存在，但不能跨越多个文件
- 无名命名空间中定义的变量拥有静态生命周期
- 无名命名空间中的名字的作用域和该命名空间所在的作用域相同

> 无名命名空间的行为类似于 C 语言中为变量添加`static`关键字的行为，将其生命周期提升为静态生命周期
