C++ 的异常处理是通过**抛出异常->处理异常**这样的方式进行的。

- 抛出异常：通过`throw`表达式进行异常的抛出
- 处理异常：如果抛出的异常没有实际的代码进行管理，那么就由系统进行处理；如果通过`try`语句块中的`catch`进行了捕获，那么就将由该`catch`子句进行处理。

可以说，`try`语句块就是将异常的抛出和异常的处理联系起来的方式，将任何可能抛出异常的代码包含在`try`语句中，然后在`catch`子句中去捕获并处理所有需要捕获和处理的异常。而在这个过程中，被抛出和捕获的异常实际上是一组**异常类**的对象。

### 1. 基本格式

- `throw`表达式：

  ```cpp
  throw ExceptionType(initializer);
  ```

  - `ExceptionType`是某种异常类，`ExceptionType(initializer)`也就是创建了一个该类型的对象并抛出。
  - `initializer`是用于初始化这个异常类对象的初始值，对部分异常类来说不需要初始值，其余的都需要一个字符串作为初始值，这个字符串可以是 C 风格字符串，也可以是一个`string`对象

- `try`语句块

  ```cpp
  try {
  	program-statements
  } catch (ExceptionType err_var) {
  	handler-statements
  } catch (ExceptionType2 err_var) {
  	handler-statements
  } // ...
  ```

  - `try`语句总是和`catch`子句一起使用，如果没有`catch`子句，那么`try`语句也没有了意义
  - `try`语句中总是包含`throw`表达式或可能会抛出异常的代码（例如包含`throw`表达式的函数的函数调用表达式）
  - 每个`catch`子句都可以看作是一个函数定义，将小括号里面的内容看作一个形参声明，在该`catch`子句中可以直接作为一个局部变量使用。如果在`try`语句中抛出了一个异常，那么在所有关联的`catch`子句中，只要有形参类型和这个异常类型相同的`catch`子句，那么被抛出的这个异常对象就会作为这个`catch`子句的实参传入，并进入该`catch`子句执行对应的处理代码

### 2. 示例

```cpp
Sales_item item1, item2;
while (cin >> item1 >> item2) {
    try {
    	if (item1.isbn() != item2.isbn())
    		throw runtime_error("Data must refer to same ISBN");
    	cout << item1 + item2 << endl;
    } catch (runtime_error err) {
    	cout << err.what()
    		 << "\nTry Again? Enter y or n" << endl;
    	char c;
    	cin >> c;
    	if (!cin || c == 'n')
    		break;
    }
}
```

使用`try`语句块可以有效的将程序逻辑和异常处理代码分离开



### 3. 被抛出异常的匹配路径

一个`throw`表达式可能明显地包含在一个`try`语句块，也可能并不明显地包含在`try`语句块中（例如，在实际抛出异常的函数中并没有将其放在`try`语句中，但是这个函数的调用表达式却放在一个`try`语句中），这并不重要。

当异常被抛出时，将首先搜索其本身所在的`try`语句块中的`catch`子句，如果其本身没处在`try`语句块中或没找到匹配的`catch`子句，则**终止该函数**，并在该函数的调用表达式所处的`try`语句块中查找，如果该调用表达式没处在`try`语句块中或没找到匹配的`catch`子句，则以此类推，直到找到适当类型的`catch`子句为止，这个过程称之为**栈展开**。如果最终还是没能找到任何匹配的`catch`子句，那么程序将转到名为`terminate`的标准库函数，该函数的行为与系统有关，一般情况下，执行该函数将导致程序非正常退出。

### 4. 重要事项

#### 1）抛出异常

- 如果匹配到了一个`catch`子句，那么当该子句执行完成后，将从该`catch`子句所处的`try`语句块所关联的所有`catch`子句中最后一个`catch`子句之后的位置开始执行。

- 在栈展开的过程中，位于调用链上的语句块可能会提前退出，这些块中创建的一些局部对象将被自动销毁（被抛出的**异常对象**除外，它位于由编译器管理的空间中，当异常处理完毕后，异常对象才被销毁）。如果异常发生在构造函数中，则当前的对象可能只构造了一部分。即使某个对象只构造了一部分，我们也要确保已构造的成员能被正确地销毁。同样，异常也可能发生在数组或标准库容器的元素初始化过程中，如果在异常发生前已经构造了一部分元素，我们应该确保这部分元素被正确地销毁。

- 如果块中分配了资源，并打算在块的末尾手动释放这块资源，那么如果在负责释放这些资源的代码前面发生了异常，则释放资源的代码将不会被执行。所以为了更安全的资源管理，最好用类给这些资源封装一下，使用类对象而非直接分配资源。

- 析构函数不应该抛出不能被它自身处理的异常。也就是说，如果析构函数需要执行某个可能抛出异常的操作，则该操作应该被放置在一个`try`语句块中，并在析构函数内部得到处理。

- 被`throw`表达式抛出的对象都称为**异常对象**，而不管其实际的类型是否是一个标准异常类。内置类型和其他类类型也可以被抛出。如果该表达式抛出的是数组类型或函数类型，则被转换为与之对应的指针类型。如果该表达式抛出的是类类型对象，则要求：

  - `throw`表达式必须拥有完全类型
  - 该类型必须含有一个可访问的析构函数和一个可访问的拷贝或移动构造函数。

- 被抛出的表达式类型不应该是一个指向局部对象的指针，这个指针本身会通过拷贝初始化保存为异常对象，但其所指的对象会在块退出时被释放。

  如果被抛出的表达式类型是一个数组，它将被转换为指针。但是数组本身会作为异常对象保存，不会被释放。而如果抛出的表达式是一个局部数组对象的数组名，那么在表达式处就直接转换为了指针，所以抛出的表达式是一个指针而非数组，其效果和上述的抛出指针的效果相同，局部数组会在块退出时被释放。

- 当我们抛出一条表达式时，该表达式的静态编译时类型决定了异常对象的类型决定了异常对象的类型。例如：

  ```cpp
  class Derived : public Base { /* ... */ };
  
  void func() {
      Derived d;
      Base *pb = &d;
      throw *pb;
  }
  ```

  上述代码中第 6 行所抛出的解引用表达式实际上得到的是`Base`类型的对象，所以被保存的异常对象是`Base`类型的，因为异常对象并非指针或引用，所以在拷贝过程中，派生类对象`d`的非基类部分就被切掉了。同时，由于前述特点，我们不应该抛出局部对象的指针，所以不能直接抛出`pb`。



#### 2）捕获异常

- `catch`子句的异常声明的类型必须是完全类型。另外，它可以是左值引用，但不能是右值引用。

- 在搜寻`catch`语句的过程中，我们最终找到的`catch`未必是异常的最佳匹配。挑选出来的应该是第一个与异常匹配的`catch`语句。因此，越是专门的`catch`月应该置于整个`catch`列表的前端。

- 异常对象和`catch`子句的异常声明类型的匹配规则不允许绝大多数类型转换，除了以下的类型转换之外，要求异常对象的类型和`catch`声明的类型是精确匹配的：

  - 允许从非常量向常量的类型转换
  - 允许从派生类向基类的类型转换
  - 数组被转换成指向数组（元素）类型的指针，函数被转换为指向该函数类型的指针

- **重新抛出**：有时，一个单独的`catch`语句不能完整地处理某个异常。在执行了某些校正操作之后，当前的`catch`可能会决定由调用链更上一层的函数接着处理异常。通过重新抛出的操作：

  ```cpp
  throw;
  ```

  这里的重新抛出仍然是一条`throw`语句，只不过不包含任何表达式。

  空的`throw`语句只能出现在`catch`语句或`catch`语句直接或间接调用的函数之内。如果在处理代码之外的区域遇到了空`throw`语句，编译器将调用`terminate`.

  重新抛出语句会将当前的异常对象沿着调用链向上传递。如果重新抛出语句所在的`catch`子句对这个异常对象进行了修改，且该`catch`的参数声明是一个引用类型，那么重新抛出时将是改变之后的值，否则是改变之前的值。

- **捕获所有异常**：下面的`catch`子句可以捕获所有类型的异常对象：

  ```cpp
  catch (...) {
      // ...
  }
  ```

  `catch(...)`既能单独出现，也能与其他的`catch`语句一起出现。如果一起出现，那么`catch(...)`必须在最后的位置，否则出现在`catch(...)`后的`catch`语句将永远不会被匹配。

#### 3）函数`try`语句块与构造函数

如果构造函数在初始值列表处抛出了异常，在构造函数体内是无法进行处理的。此时需要写作**函数`try`语句块**，也称为函数测试块：

```cpp
template <typename T>
Blob<T>::Blob(std::initializer_list<T> il) 
    try : data(std::make_shared<std::vector<T>>(il)) { }
catch(const std::bad_alloc &e) { handle_out_of_memory(e); }
```

与这个`try`关联的`catch`既能处理构造函数体抛出的异常，也能处理成员初始化列表抛出的异常。



#### 4）`noexcept`异常说明

`noexcept`说明可以指定某个函数不会抛出异常，其形式是关键字`noexcept`紧跟在函数的参数列表后面：

```cpp
void recoup(int) noexcept;
void alloc(int);
```

对于一个函数而言，`noexcept`说明必须在函数的声明和定义中都出现。也可以在函数指针的声明和定义中指定`noexcept`。而在`typedef`或类型别名中则不能出现`noexcept`。在成员函数中，`noexcept`说明符需要跟在`const`及引用限定符之后，而在`final`、`override`或虚函数的`=0`之前。

****

**违反异常说明**：

如果一个函数在说明了`noexcept`的同时又含有`throw`语句或者调用了可能抛出异常的其他函数，编译将顺利编译通过。

在这种情况下，程序也会调用`terminate`来处理异常。因此，`noexcept`可以用在两种情况下：一是我们确认函数不会抛出异常，二是我们根本不知道该如何处理异常。

****

**异常说明的形参**：

`noexcept`说明符接受一个可选的实参，该实参必须能够转换为`bool`类型；如果实参是`true`，则函数不会抛出异常；如果实参是`false`，则函数可能抛出异常：

```cpp
void recoup(int) noexcept(true);
void alloc(int) noexcept(false);
```

****

**`noexcept`运算符**：

`noexcept`运算符用于判定给定的表达式是否可能抛出对象，返回`bool`值：

```cpp
noexcept(recoup(i))		// 返回 true
noexcept(alloc(i))		// 返回 false
```

****

**异常说明与指针、虚函数和拷贝控制**：

- 如果一个函数指针做了不抛出异常的声明，那么该指针只能指向不抛出异常的函数
- 如果我们显式或隐式地说明了指针可能抛出异常，则该指针可以指向任何函数，即使是承诺了不抛出异常的函数也可以
- 如果一个虚函数承诺了不抛出异常，则后续派生出来的虚函数也必须做出同样的承诺；如果基类的虚函数允许抛出异常，则派生类的对应函数既可以允许抛出异常，也可以不允许抛出异常。
- 当编译器合成拷贝控制成员时，同时也生成一个异常说明。如果对所有成员和基类的所有操作都承诺了不会抛出异常，则合成的成员是`noexcept`的。如果合成成员调用的任意一个函数可能抛出异常，则合成的成员是`noexcept(false)`的。而且，如果我们定义了一个析构函数但是没有为它提供异常说明，则编译器将合成一个。合成的异常说明将与假设由编译器为类合成析构函数时所得的异常说明一致。
