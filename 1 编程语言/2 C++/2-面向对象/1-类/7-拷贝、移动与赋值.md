## 一、拷贝构造函数

- 一个构造函数的第一个参数是自身类类型的引用，且任何额外参数都有默认值，则此构造函数是拷贝构造函数

- 拷贝构造函数的第一个参数必须是一个引用类型。否则会出现无法调用的情况，如果不是引用类型，那么在调用拷贝构造函数的时候将实参传递给形参时又会调用拷贝构造函数，导致一个无法返回的循环调用链

- 参数通常是常量引用类型，也可以定义为非常量引用类型，但会导致无法使用常量对象作为拷贝初始化时的初始值

- 拷贝构造函数在几种情况下都会被隐式地使用，所以拷贝构造函数通常不应该是`explicit`的

- **编译器优化**：编译器可能将一个拷贝初始化优化为直接初始化，例如：

  ```cpp
  string null_book = "9-999-99999-9";
  ```

  优化为

  ```cpp
  string null_book("9-999-99999-9");
  ```

  但即使编译器跳过了拷贝/移动构造函数，在实际代码的语义下，拷贝/移动构造函数必须存在且可访问

### 1. 合成拷贝构造函数

- 如果没有为一个类定义拷贝构造函数，编译器会合成一个拷贝构造函数
- 和默认构造函数不同，即使我们定义了其他构造函数，编译器也会为我们合成一个拷贝构造函数
- 合成的拷贝构造函数会将其参数的各个成员逐个拷贝到正在创建的对象中
  - 对类类型的成员，会使用其拷贝构造函数来拷贝
  - 内置类型的成员则直接拷贝（所有拷贝皆为浅拷贝）
  - 对于数组则逐元素地拷贝每一个成员
- 使用`=default`取代构造函数初始值列表和函数体，显式使用编译器合成的拷贝构造函数

### 2. 阻止拷贝构造函数

- 将拷贝构造函数定义为`=delete`的，即删除拷贝构造函数
- 合成的拷贝构造函数在下面的情况下是删除的：
  - 类的某个成员的拷贝构造函数是删除的或不可访问的
  - 类的某个成员的析构函数是删除的或不可访问的
  - 类定义了一个移动构造函数或一个移动赋值运算符



## 二、拷贝赋值运算符

- `operator=`运算符重载函数，唯一的参数接受自身类类型的引用（和拷贝构造函数一样，通常也是常量引用。但和拷贝构造函数不同的是，不强制要求是引用类型），返回指向其左侧运算对象的引用（不需要重载，使用到了拷贝赋值运算符的对象不会是常量对象）
- 赋值运算符需要先检查自赋值的情况

### 1. 合成拷贝赋值运算符

- 如果没有定义自己的拷贝赋值运算符，编译器会合成一个拷贝赋值运算符
- 合成的拷贝赋值运算符将右侧运算对象的各个成员赋值给左侧运算对象的对应成员（仍然是浅拷贝），然后返回左侧运算对象的引用
- 使用`=default`取代函数体，显式使用编译器合成的拷贝赋值运算符

### 2. 阻止拷贝赋值运算符

- 将其定义为`=delete`的，即删除拷贝赋值运算符
- 合成的拷贝赋值运算符在下面的情况下是删除的：
  - 类的某个成员的拷贝赋值运算符是删除的或不可访问的
  - 类有一个`const`成员或引用成员
  - 类定义了一个移动构造函数或一个移动赋值运算符



## 三、移动构造函数

- 第一个参数接受一个非`const`的右值引用（语法允许是`const`的，但没有意义），任何额外的参数都必须有默认实参
- 移动构造函数通常的行为是从给定对象“窃取”资源，然后将源对象置为即使销毁也无害的一个状态。
  以管理堆内存的指针为例，可以直接进行浅拷贝，但需要将源对象中管理这块堆内存的指针置为空，否则按照通常的析构逻辑，源对象会在析构时释放其所管理的内存或对其管理逻辑造成有害影响。
- 移动构造函数通常需要`noexcept`关键字进行说明，其位置在参数列表之后构造函数初始值列表之前，声明和定义中都需要

### 1. 合成的移动构造函数

- 当类定义了拷贝构造函数、拷贝赋值运算符或析构函数时，编译器不会为该类合成移动构造函数，需显式定义
- 当类没有定义任何拷贝控制成员，且类的每个非`static`数据成员都可以移动时（内置类型可移动，类类型需要有对应的移动操作），编译器会为其合成移动构造函数
- 使用`=default`作为函数定义可以显式使用合成的移动构造函数，但如果编译器不能移动所有成员，则编译器会将移动操作定义为删除的函数，具体有以下情况
  - 类成员定义了自己的拷贝构造函数且未定义移动构造函数，或类成员未定义自己的拷贝构造函数且编译器不能为其合成移动构造函数
  - 如果类成员的移动构造函数被定义为删除的或是不可访问的
  - 类的析构函数被定义为删除的或不可访问的



## 四、移动赋值运算符

- 移动赋值运算符执行与析构函数和移动构造函数相同的工作。通常接受一个非`const`的右值引用，返回左侧运算对象的引用
- 移动赋值运算符需要先处理自赋值的情况
- 需要使用`noexcept`关键字进行说明
- 需要保证移动完成后源对象处于析构无害的状态

### 1. 合成的移动赋值运算符

- 当类定义了拷贝构造函数、拷贝赋值运算符或析构函数时，编译器不会为该类合成移动赋值运算符，需显式定义
- 当类没有定义任何拷贝控制成员，且类的每个非`static`数据成员都可以移动时（内置类型可移动，类类型需要有对应的移动操作），编译器会为其合成移动赋值运算符
- 使用`=default`作为函数定义可以显式使用合成的移动赋值运算符，但如果编译器不能移动所有成员，则编译器会将移动操作定义为删除的函数，具体有以下情况
  - 类成员定义了自己的拷贝赋值运算符且未定义移动赋值运算符，或类成员未定义自己的拷贝赋值运算符且编译器不能为其合成移动赋值运算符
  - 如果类成员的移动赋值运算符被定义为删除的或是不可访问的
  - 类有`const`成员或引用成员



## 五、拷贝并交换赋值运算符

- 当重载赋值运算符函数接受的参数不是引用类型而是类类型时，它既是一个移动赋值运算符，也是一个拷贝赋值运算符

- 在这个函数里，可以世界使用`swap`进行实现，例如：

  ```cpp
  HasPtr& operator=(HasPtr rhs)
  {
      swap(*this, rhs);
      return *this;
  }
  ```
